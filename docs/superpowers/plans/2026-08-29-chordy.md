# Chordy Implementation Plan

> **For agentic workers:** This plan is executed inline in this session per the project brief (single-pass build, no Gradle invocation). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A floating overlay character that reacts emotionally to charger plug/unplug events in one of three personalities, with escalating moods, cloud LLM lines (canned fallback), and cloud TTS (silent fallback).

**Architecture:** Foreground service listens for power broadcasts → updates persisted mood state → overlay bubble shows line instantly (canned) with LLM upgrade-in-place → TTS speaks final line when audio lands. Koin wires it all; SharedPreferences persists mood (5 scalars — Room would be ceremony); EncryptedSharedPreferences holds keys.

**Tech Stack:** Kotlin 2.1, Jetpack Compose (Settings UI only), plain Android Views for the overlay (no Compose in WindowManager — avoids lifecycle-owner hacks and recomposition churn on an always-on-screen view), Koin 4, Retrofit + OkHttp, MediaPlayer.

## Global Constraints
- minSdk 26, targetSdk/compileSdk 35, package `com.kaiser.chordy`
- No hardcoded API keys — EncryptedSharedPreferences only
- Every network call: ≤3s timeout + graceful fallback (LineBank / silent skip)
- Overlay: no recomposition loops — plain View invalidation
- No `TODO`s in core logic paths
- No Gradle build in this session — code + repo only
- Debounce: power events <2s apart ignored
- Mood tiers: 0–1 reconnects = CALM, 2–3 = ANXIOUS, 4+ = ANGRY
- LLM response ≤ ~40 tokens; 3s timeout; LineBank fallback on any failure
- TTS failure = silent skip, text bubble still works

## Task Order

### Task 1: Gradle scaffold ✅ (done)
settings.gradle.kts, root + app build.gradle.kts, version catalog (AGP 8.9.2 / Kotlin 2.1.10 / Koin 4.0.4 / Retrofit 2.11), wrapper 8.13.

### Task 2: Manifest + resources
`AndroidManifest.xml` (permissions: SYSTEM_ALERT_WINDOW, FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE, POST_NOTIFICATIONS, INTERNET, RECEIVE_BOOT_COMPLETED; service + activity + boot receiver), strings.xml, themes.xml, adaptive icon, backup rules.

### Task 3: data layer
- `data/Personality.kt` — enum CLINGY/TOXIC_EX/DRAMATIC_ACTOR, persona system prompt per personality, voice-style tag
- `data/LineBank.kt` — canned lines, ~4 per personality per mood tier (12 per personality, 36 total), event-type aware (PLUG/UNPLUG/reconnect variations), rotating index so repeats don't fire back-to-back
- `data/MoodState.kt` — reconnectCount, timestamps, selected personality; MoodTier enum CALM/ANXIOUS/ANGRY with threshold logic; persist/load
- `data/SettingsStore.kt` — EncryptedSharedPreferences for keys/URLs/model/voice IDs + AI-lines toggle + personality selection; plain prefs for non-secrets

### Task 4: network + audio
- `network/LlmClient.kt` — OpenAI-compatible /chat/completions via Retrofit @Url (base URL from settings); system prompt + mood + event + count; max_tokens ~48; 3s timeouts via OkHttp; returns line or null
- `network/TtsClient.kt` — Fish Audio-style POST {text, voice_id} → audio bytes (also supports raw OpenAI TTS JSON → b64 audio); plays via AudioPlayer
- `audio/AudioPlayer.kt` — MediaPlayer, temp-file handoff on main thread, cancel/replace in-flight

### Task 5: overlay
- `overlay/OverlayManager.kt` — WindowManager add/remove, drag layout params (edge-position fixing), tap-to-expand speech bubble, mood face swap
- `overlay/BubbleView.kt` — custom View drawing the character face (eyes + mouth per MoodTier) via Canvas, 48dp idle bubble; speech bubble with current line + subtle loading dots while TTS pending

### Task 6: service + app shell
- `service/PowerMonitorService.kt` — FGS with low-priority persistent notification, power broadcast receiver, 2s debounce, MoodState updates, overlay trigger, battery-optimization exemption request on first run
- `service/BootReceiver.kt` — restart monitoring after reboot (RECEIVE_BOOT_COMPLETED)
- `ChordyApp.kt` — Application, Koin module: SettingsStore, LlmClient, TtsClient, AudioPlayer, OverlayManager, PowerMonitorService deps
- `MainActivity.kt` — first-launch permission flow (overlay, POST_NOTIFICATIONS, battery exemption), starts service, hosts SettingsScreen
- `ui/SettingsScreen.kt` — Compose: personality radio group, LLM key/base URL/model fields, TTS key/base URL/voice-ID fields (per-personality voice ID map), AI-lines toggle, reset counter, test-line button
- `ui/Theme.kt` — Material3 theme

### Task 7: docs + hygiene
README.md (app description, 3 personalities, setup, keys-in-Settings note, no-CI note), DECISIONS.md, .gitignore.

### Task 8: verification sweep
Cross-file import/reference check (grep all class refs, manifest entries), self-check list from brief, then commit + push.
